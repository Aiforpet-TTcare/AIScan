# TDD80 Visual Audit — Phase A

This directory records the first public UI regression baseline for the secure
Objective-C SDK split. It is intentionally checked in so that light-mode
appearance cannot be changed accidentally while adding dark-mode support.

## Baselines

| File | Contract |
| --- | --- |
| `01_camera_ready_light.png` | Camera ready state while the host is in light mode |
| `01_camera_ready_dark.png` | Camera ready state while the host is in dark mode |
| `02_camera_error_retry_light.png` | Camera error and retry state while the host is in light mode |
| `02_camera_error_retry_dark.png` | Camera error and retry state while the host is in dark mode |
| `03_result_light.png` | Result screen with the 2.2.4 light palette and framed unselected symptom chips |
| `03_result_dark.png` | Result screen using adaptive dark colors |
| `04_result_accessibility_light.png` | Result screen at an accessibility Dynamic Type size in light mode |
| `04_result_accessibility_dark.png` | Result screen at an accessibility Dynamic Type size in dark mode |

`ValidationHost/` contains five full-app simulator captures produced by the
branch-only validation host:

| File | Contract |
| --- | --- |
| `05_result_ko_light.png` | Korean captions and framed tabs in light mode |
| `05_result_ko_dark.png` | Korean captions and framed tabs in dark mode |
| `06_result_en_light.png` | English package localization selected at runtime |
| `07_result_ja_light.png` | Japanese package localization selected at runtime |
| `08_camera_error_retry_host_light.png` | Fixed-dark camera fallback and retry UI under a light host |

The host declares English, Korean, and Japanese in its main bundle. This is
required for the system to select matching localizations from package resource
bundles; consumer apps must likewise declare the languages they support.

The camera is a fixed-dark capture surface by design. Its light-host and
dark-host images must therefore be pixel-identical. The result screen is
adaptive, so its light and dark images must differ. The Korean image captions
are deliberately distinct: `원본 사진` and `AI 분석 사진`.

These images are generated by `AIScanCompatibilityTests` and are attached to
the XCTest result bundle on every run. The checked-in copies were exported from
the successful TDD80 Phase A test result.

The `ValidationHost` images are generated by
`SecureSplitValidationHostUITests`. They are simulator evidence only. The same
tests must be rerun with a connected supported iPhone before device sign-off.

## Remaining TDD80 coverage

Phase A is not the complete TDD80 sign-off. Before the secure split can ship,
the following flows still require device-level visual evidence against the
released 2.2.4 application:

- live camera permission states and the real preview layer;
- album selection, capture progress, diagnosis, and dismissal transitions;
- result screens populated with real original and analysis images;
- English and Japanese layouts on a physical device;
- a complete 2.2.4-versus-split screenshot comparison on supported devices.
